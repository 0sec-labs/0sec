## Native integration smoke — 2026-09-10

The provisioned FoxGuard 0.12.0 binary scanned six temporary source fixtures
through its real JSON reporter, without Semgrep or a model:

| Language | Positive fixture | Observed rule IDs | Clean control |
| --- | --- | --- | --- |
| JavaScript | `eval(req.body.code)` | `js/taint-eval`, `js/no-eval` | `JSON.parse(req.body.code)` — no findings |
| Python | `eval(data)` | `py/no-eval` | `json.loads(data)` — no findings |
| PHP | `eval($_POST['code'])` | `php/no-eval` | `json_decode($_POST['code'], true)` — no findings |

Each report recorded one scanned file. Positive cases exited 1 with findings;
controls exited 0. These are obvious synthetic fixtures, not a recall/precision
benchmark or independent exploit verification. The comparison gates above
remain unmeasured.

A direct scan of the checked-in `__tests__/fixtures/vuln-eval.js` instead
reported zero scanned files because FoxGuard classified the path as noise.
Zero findings must therefore be read alongside coverage metadata; an excluded
fixture is not a clean negative control.
